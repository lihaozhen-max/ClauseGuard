## 3. 关键发现与实现决策

M3 又踩出两个**解析层的隐蔽缺陷**（都被规则用例逼出来）——它们不在规则引擎里，但直接决定规则能不能读到正确的合同部位。

### 3.1 【R-01】条款区间只在下一条"含关键词"的标题处断开（已修）

**现象**：AP-001 的争议解决条款区间是 221 字符（实际约 56），一路吞到文末。

**根因**：`_clause_span` 只在"被 `clause_heading_index` 判定为条款起点"的段落断开，
而该函数只登记**命中 §2.9 词表**的标题。于是"第八条 合同期限与续约""第九条 其他"
这些不含关键词的编号条款不构成断点，争议解决条款把后半篇全圈了进去。

**后果**：R003（自动续约）的 target_section 是"dispute_clause 之外的全文"，
"本合同期满自动续约一年。"被误判为位于争议解决部位内而被**排除**，
关键词命中被跳过 → 本该 hit 的 R003 变成 uncertain（LLM 关闭时）。

**修法**：**任何** `第X条 / 第X章` 都是新条款的起点，与是否含关键词无关。

### 3.2 【R-02】"短段落即标题"把正文短句当成条款标题（已修）

**现象**：合成用例里付款条款区间只剩标题 `第三条  付款方式`（9 字符），正文的账期读不到，
R002 变成 uncertain。

**根因**：短标题规则是"≤24 字 + 非列表项"。正文短句 `验收合格后120日内支付尾款。`
（15 字、含"验收"、验收条款当时尚未被认领）因此被登记为验收条款标题，
**把上一条（付款）的正文截断**。

**修法**：短标题**不得以句末标点结尾**（`。！？；.!?;`）。标题不会以句号收尾，正文句子会。

> 这两处都是"部位定位错了但结果**看起来**还算合理"的缺陷——只有把规则的期望命中钉死
> （SD-01 基线 + 逐条正反例）才能发现。已各补一条回归用例。

### 3.3 【R-03】`clear_signals` 过宽导致误判"归属已明确"（已修）

种子里的 `clear_signals` 含 `知识产权归`，而 `双方就知识产权归属另行协商确定。`
恰好包含该子串 → R010 被误判为"已明确约定归属"而漏报。
已收紧为 `归甲方所有 / 归甲方 / 甲方享有 / 归属甲方 / 甲方独立享有`。

### 3.4 LLM 客户端必须可注入（IF-16 踩坑）

IF-16 走接口层时未注入 LLM，`run_rules_for_task` 便按配置构建了**真实 DeepSeek 客户端**，
测试因此触发真实调用（每条语义规则最多 60s × 2 次重试）→ 测试挂起。
修法：新增 `app/api/deps.get_llm_client`（进程级单例 + FastAPI 依赖），测试用
`dependency_overrides` 注入 `NullLLMClient`。**生产默认仍是真实端点**。

### 3.5 测试中跨事件循环复用 engine（已修）

`TestClient`（portal 循环）与 `db_runner`（`asyncio.run` 临时循环）混用时会抛
`Future attached to a different loop`——engine 是进程级单例，且**不能**在新循环里
await 旧循环的 `dispose()`。修法：新增 `reset_engine_state()`（只丢引用不 await），
`db_run` 每次先丢弃缓存再自建。

### 3.6 `judge_semantic` 兜住一切异常（LM-14）

客户端实现（或未来的新端点适配器）抛出的异常不得穿透到规则层——LLM 是增强项，
坏掉只能降级为 `uncertain`，不能把整条审查链打断。

### 3.7 规则参数的承载方式（§2.2 枚举不可扩展）

SPEC §8 里 R004/R010/R011 的 `match_mode` 写作 `"presence + llm_semantic"`，
但 §2.2 规定 `match_mode` 只能是 5 个值之一且**禁止扩展**。因此：

- DT-04 里存**确定性主模式**（`presence` / `keyword`）；
- LLM 阶段、不对等信号、四要素清单、验收三要素正则等放在 `match_params_json`；
- 代码里 `HANDLERS[rule_code]` 给出专用实现，未注册的规则按 `match_mode` 走通用匹配器。

### 3.8 缺失型命中的证据口径

R004①/R008/R010①/R011① 是"条款不存在"型命中，**没有原文可引**。
SPEC RL-004① 写"证据取最接近条款上下文"，但"最接近"缺乏可判定定义，
硬取上下文会把无关文字当证据。因此统一取 `evidence_text = evidence_position = null`，
并在 §4.6.1 的评论模板里按规范改用"建议行"（模板本就为此设计了该分支）。
字段本身始终存在（§2.4 结构完整），只是值为 null。

### 3.9 其他口径

- **`rule_hits` 落库含 miss / uncertain**：不只存 hit，便于审计与 IF-15 完整回放（AC08 要求返回全部 11 条判定）；
- **重复运行不删除已停用规则的历史命中**（NF-04：不得丢失已生成数据），只覆盖本次评估到的规则；
- **`uncertain` 不计入整体等级**（RL-AGG-01），但保留在结果里供人工确认（FR-REV-06）；
- **LLM 上下文**只送相关部位（`semantic_context` 优先给 target_section 文本），省 token 且降低误判。
