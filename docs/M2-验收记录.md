## 3. 关键发现与实现决策

M2 是"踩坑最多"的一个里程碑：OCR 链路有两个**必须绕过**的环境缺陷，字段抽取有两个**实测发现**的判定错误。

### 3.1 【R-01】Paddle 无法读取含非 ASCII 字符的模型路径（Windows）

**现象**：OCR 引擎初始化时抛
`RuntimeError: [json.exception.parse_error.101] parse error at line 1, column 1: attempting to parse an empty input`。

**定位过程**：模型文件本身完整且合法（`inference.json` 312 KB 可正常 `json.loads`、`inference.pdiparams` 62 MB），
`get_model_paths()` 返回的路径也正确。做对照实验后确认根因是**路径**：

```
[中文路径] 失败：json.exception.parse_error.101 … attempting to parse an empty input
[ASCII 路径] 成功创建 predictor：1 个输入
```

本项目位于 `C:\Users\13273\Desktop\项目实战2\...`，而 CF-21 默认的 `./storage/ocr_models` 就在该目录下，
因此**默认配置在中文路径的机器上必然失败**。

**尝试过但不可行**：Windows 8.3 短名——本机的短名仍是中文（`项目实~1`），拿不到 ASCII 路径。

**决策**：
- `OCR_MODEL_DIR` 默认值由 `./storage/ocr_models` 改为**空**，空 = 自动选择 ASCII 安全目录
  `%LOCALAPPDATA%\ClauseGuard\ocr_models`；
- 新增 `Settings.ocr_cache_dir`：**保证 ASCII**，配置了非 ASCII 路径时自动回退并记 WARNING；
- `.env.example` 明确写出"不要指向含中文的路径"及原因。

> 这是对 SPEC CF-21 的一处**必要偏离**，请确认（见 §5）。

### 3.2 【R-02】paddle 3.3.1 的 PIR 执行器在 oneDNN/MKLDNN 路径上有缺陷

**现象**：`NotImplementedError: (Unimplemented) ConvertPirAttribute2RuntimeAttribute not support
[pir::ArrayAttribute<pir::DoubleAttribute>] (at …/new_executor/instruction/onednn/onednn_instruction.cc:118)`

**定位过程**：先怀疑模型版本，依次实测 `PP-OCRv6`/`PP-OCRv5`/`PP-OCRv4` —— **三者全部失败**，
说明与模型无关；错误位置在 `onednn_instruction.cc` 指向了执行器路径。查 PaddleOCR 源码发现
`DEFAULT_ENABLE_MKLDNN = True`，CPU 设备下 `run_mode` 落到配置默认的 `mkldnn`。

**决策**：调用 `PaddleOCR(..., enable_mkldnn=False)` → CPU 走纯 Paddle 内核，问题消失
（`PP-OCRv6` 实测识别 20 行，置信度 0.95+）。新增补充配置 `OCR_ENABLE_MKLDNN`（默认 `false`，
SPEC §11 未列，`.env.example` 注明必须保持 false）。

### 3.3 【R-03】OCR 会把数字识别成被空格切开

实测 `80%` → `8 0 %`、`20个` → `2 0个`、`￥200000.00` → `￥2 0 0 0 0 0.0 0`。
不修复会直接影响 M3 的阈值类规则（R001 预付款比例、R002 付款账期）。
`cleaning.normalize_ocr_text()` 只在 OCR 文本上做"数字-空格-数字/百分号"合并，
**不碰**数字与中文之间的空格（`服务器 20 台` 保持原样）。

### 3.4 【R-04】段落切分：`PyMuPDF block == 段落`

先实测再决定，避免脆弱的启发式：样例 PDF 的第 1 页被 PyMuPDF 切成 **19 个 block**，
第 2 页 **15 个**，与文本源的段落结构**完全一致**。因此：

- 文本型 PDF：block 即段落候选，块内多行按"折行还原"规则合并；
- OCR 页：整页合成一个 block，由 `cleaning.split_line_indices` 用三条信号切分
  （断句符 / 段落起始标志 / 明显短于该块最长行）；
- 两种来源共用同一套切分与清洗逻辑，`full_text` 由段落按 `\n` 拼接，
  保证**每段文本都是 `full_text` 的连续子串**——这是 PS-10 证据回验成立的前提。

### 3.5 【R-05】条款标题误判（实测发现的真实缺陷）

第一次跑 AP-002 时，`acceptance_clause` 被定位到付款条款里：

```
acceptance_clause  success  第1页 第14段  值=2. 服务期满并经甲方验收合格后30日内支付剩余70
```

原因是该段落以 `2.` 开头（命中列表项正则）且含"验收"二字，被当成了条款标题。
**修法**：只有 `第X条 / 第X章` 才算"带编号的条款标题"；"短段落即标题"这一档
**必须排除列表项标记**（`1.`/`（1）`/`一、`）。修复后 AP-002 的验收条款正确定为
`第1页 第18段 → 第五条 验收条款`，并补了回归用例。

### 3.6 【R-06】中文大写金额字符集漏字

`人民币([零一二三四五六七八九十百千万亿贰叁肆伍陆柒捌玖拾佰仟两]{2,20}?)元` 的字符集
混排了大小写两套数字，但**漏了"壹"**，导致 `壹佰贰拾万元整`（1200000）取不到值。
已补齐并在模块内加了 `assert`，让"词表与会话表漂移"在导入期就暴露。

### 3.7 【R-07】失败路径必须显式 commit

`download_contract_attachment` / `parse_task` 在异常路径上会写"blocked 状态 + error_code + 日志"，
如果直接让异常穿出 `session_scope()`，会话关闭时不提交，**失败现场就丢了**（违反 NF-04）。
因此工具层统一用 `try/except AppError: await session.commit(); raise` 保住失败数据。

### 3.8 【R-08】blocked 状态下重入视为人工重试

`download`/`parse` 在任务已 `blocked` 时再次被调用，按 ST-01 的 `blocked → parsing/reviewing`
迁移处理（`transition_to` 会清空 `blocked_stage`/`error_code` 并 `retry_count += 1`，ST-01-02）。
这样 M5 的 IF-20 人工重试可以直接复用这两条路径，不必另写一套。`done` 任务**禁止**回退（ST-01-03）。

### 3.9 【R-09】`parse_status` 口径

`missing`（条款在合同里确实不存在，如采购合同没有保密条款）**不算** `partial`——
它是规则的判定依据（R008/R010 靠它命中），不是提取故障。
口径：存在 `failed` → `partial`；全部字段都取不到 → `failed`；其余 → `success`。

### 3.10 【R-10】混合文档的位置格式

PS-05 要求混合文档 `parse_mode` 取 `ocr`（position 格式唯一）。为免出现"无坐标的 OCR 位置"，
**文本页也记录文本框坐标**（`get_text("dict")` 的逐行 bbox），于是混合文档里所有段落都能给出
`区域(x,y)`。纯文本文档仍走 `第N页 第M段`。

### 3.11 其他口径

- **`document_id` 双口径**：SPEC §2.1 规定 `document_id = contract_parses.id`，但首次解析时尚无解析记录，
  故实现为"先查 `contract_parses.id`，查不到再查 `approval_attachments.id`"，使 IF-04 在任何时刻可调用。
- **PS-07/PS-08（LLM 兜底层）**：`extract_fields(llm_fallback=...)` 已预留该层并限制在 5 个关键字段，
  但 **M2 不启用**——LLM 客户端按设计 §14 属 M3，届时接入即可生效。

## 5. 需要知悉的偏离与补充（请确认）

| # | 事项 | 处理 | 原因 |
|---|---|---|---|
| **M2-A** | CF-21 `OCR_MODEL_DIR` 默认值 `./storage/ocr_models` → **空**（自动 ASCII 目录） | 默认值改为空；显式配置非 ASCII 路径时自动回退并告警 | 中文路径下 Paddle 必然加载失败（§3.1 实测），这是环境硬约束而非偏好 |
