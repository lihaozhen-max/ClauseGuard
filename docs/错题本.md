# ClauseGuard · 错题本与协作约定

| 项 | 内容 |
|---|---|
| 文档编号 | CG-LESSONS-001 |
| 用途 | 把本项目开发过程中**真实犯过的错**逐条记下来，附「以后的规则」与「怎么防呆」，避免重复踩 |
| 适用范围 | 参与本仓库开发的人（含 AI 助手）在**改代码、跑验证、写文档、汇报结论**时的自我约束 |

## A. 证据与诚实（最严重，先改这一类）

### A-1 把"没验证的"当成"验证过的"
- **现象**：验证"样例可复现生成"时，脚本其实因文件被占用 `Permission denied` 失败退出了，
  我却拿"`git status` 为空"当作"产物可复现"的证据报了出去。用户抽查时才发现。
- **规则**：凡说"验证过/已通过"，**必须紧跟命令的真实输出**；脚本非零退出就是失败，
  即使副作用看起来正常也不许当成功。失败就写"没验证到"。
- **防呆** ⚠️：先看退出码与 stderr，再看结论；不确定就重跑一次换个不撞锁的方式（例如在副本目录里跑）。

### A-2 只看汇总表就断言"实现偏离规范"
- **现象**：我依据 SPEC §10.1「LM-01 = RL-003/004/010」断言"实现里 R009 也用 LLM，属偏离"，
  但 §8.4–§8.11 **逐条**已声明 R003/004/009/010 都是 `llm_semantic`。实现没错，是汇总表列举不全。
- **规则**：判"偏离"前，先找该主题的**逐条条款**；汇总表/概览表不能当唯一依据。
- **防呆** ⚠️：写偏离说明前，先 grep 整个规范里同一关键词的所有出现位置。

### A-3 引用规范编号前不回读原文
- **现象**：我在 M3-F 里写"按 SPEC §0.2 的裁决顺序，具体条款优先于汇总列举"，
  而 §0.2 只规定**文档之间**的优先顺序，没有这条内容。
- **规则**：引用编号必须回读原文；若那是**我自己的解释**，必须显式标注"这是解释，不是规范原文"。
- **防呆** ⚠️：引用前把该节原文贴进上下文确认一次。

### A-4 谎报同步状态
- **现象**：SSH 推送被网络重置后，我用完整 HTTPS URL 推成功，却直接说"`LOCAL == REMOTE`" ——
  用完整 URL 推送**不会更新** `origin/main` 跟踪引用，当时它仍是旧的。
- **规则**：报同步必须三方一致：`rev-parse main`、`rev-parse origin/main`、`ls-remote <url> HEAD`。
- **防呆** ✅：`git status -sb` 无 `ahead/behind` 且三方哈希相同再宣布"已同步"。

## B. 工具与环境（同一类坑反复踩，最该自动化的部分）

### B-1 聊天里给的路径基准写错
- **现象**：3 次。会话工作区根是 `项目实战2/`，项目在 `ClauseGuard/` 下，
  我写 `docs/xxx.md`、`sample_contracts/xxx.pdf`，用户点开全部"文件不存在"。
- **规则**：**聊天里引用文件一律写 `ClauseGuard/...`**（仓库内部文档之间才用仓库相对路径）。
- **防呆** ⚠️：发出前对每个路径 `Test-Path` 过一遍；关键文件顺手用 `present` 登记。

### B-2 PowerShell 里用双引号拼中文/引号/`$`
- **现象**：3 次。`git commit -m "…\"多浏览器…\""` 被吃掉引号；
  `python -c "…\$null…"` 里 `$null` 被 PowerShell 展开成空 → Python 语法错误。
- **规则**：**含中文、引号或 `$` 的内容一律走文件**：提交信息用 `git commit -F 文件`，
  脚本用 `.py`/`.ps1` 文件，绝不在命令行拼字符串。
- **防呆** ✅：命令里出现 `"` 包中文时改用文件。

### B-3 把 bash 语法带进 PowerShell
- **现象**：用了 `<<'EOF'` heredoc，PowerShell 直接解析报错（且**整段命令都没执行**）。
- **规则**：先确认 shell（这里是 PowerShell 5.1/7），别套用 bash 习惯。
- **防呆** ⚠️：需要多行文本 → 写文件。

### B-4 用 `Get-Content`/`Set-Content` 往返改文件
- **现象**：一次把 `demo_closed_loop.py` 变成乱码（PS 5.1 按 ANSI 读 UTF-8 无 BOM 文件）。
- **规则**：改文件用编辑工具，或用 Python 显式 `encoding="utf-8"`；不要用 PowerShell 读写管道改源码。
- **防呆** ⚠️：改完立刻 `python -c "import ast; ast.parse(...)"` 或重新读一遍。

### B-5 `.ps1` 无 BOM
- **现象**：三个 `dev_*.ps1` 首次运行时中文全乱、甚至因某个汉字第二字节是引号而**破坏语法**。
- **规则**：**`.ps1` 必须是 UTF-8 with BOM**（PS 5.1 会按 ANSI 解码无 BOM 的脚本）。
- **防呆** ⚠️：新建/编辑 `.ps1` 后重编码为 `utf-8-sig`。

### B-6 `pytest` 传文件路径导致 rootdir 漂移
- **现象**：2 次。`uv run pytest ../tests/x.py` 会让 rootdir 变成工作区根，
  `pyproject.toml` 的 `pythonpath=["."]` 失效 → `ModuleNotFoundError: app`。
- **规则**：跑单个文件用 `-k "文件名关键字"`（保持 rootdir=backend），或 `uv run python -m pytest`。
- **防呆** ✅：本仓库统一用 `-k`。

### B-7 `Select-Object -First N` 掐断长管道
- **现象**：3 次。`... | Select-Object -First 60` 让上游进程被 SIGPIPE/终止：
  `try_contract.py` 报 `exit -1`（`finally` 里的还原一度没跑），`dev_up.ps1` 被中途杀掉。
- **规则**：长命令的完整输出**重定向到文件再读**，不要用 `-First` 截断流式输出。
- **防呆** ✅：`cmd *> out.txt` 然后 `Get-Content -Tail`。

### B-8 改了后端代码没重启就下结论
- **现象**：修好解析器后用 HTTP 跑自查合同，仍报旧行为，我差点当成"修复无效"。
  真实原因是运行中的 uvicorn 没开 `--reload`，加载的还是旧代码。
- **规则**：**改后端代码 → 重启服务 → 再验证**；用 HTTP 打接口的验证尤其要注意这一条。
- **防呆** ⚠️：改 `backend/app/**` 后先 `dev_down` + `dev_up`，再跑验证。

## C. 流程与协作

### C-1 每轮收尾把服务停掉
- **现象**：2 次。我把"停服务"当干净收尾，结果用户点开页面全是"API 请求失败"。
- **规则**：**会话进行中不停服务**；确实要停，先问一句。
- **防呆** ⚠️：收尾只清临时文件，不动进程。

### C-2 擅自扩大范围
- **现象**：把"真跨引擎浏览器验证"写进待办，而规范里根本没有这条要求，
  白占用双方的注意力，还要装 Firefox 或引 Playwright。
- **规则**：**规范外的事先问**，不要先列成"遗留问题"制造假欠账。
- **防呆** ⚠️：列待办前先问"这是 SPEC/PRD 要求的吗？"

### C-3 把"可以做的"写成"遗留/待办"
- **现象**：多次。用户因此以为欠着一堆东西。
- **规则**：严格区分 **①规范要求但没做**（真欠账）与 **②规范外可选**（建议），汇报时分开写。
- **防呆** ⚠️：每条待办标注来源编号（FR/AC/TS…）或注明"规范外"。

### C-4 临时文件漏删
- **现象**：`_audit_docs.py` 残留 —— 因为同一段命令里 PowerShell 解析报错（B-3），**整段都没执行**，
  删除步骤也被跳过。
- **规则**：清理动作**单独执行并复核**；不要在"可能解析失败的长命令"里附带清理。
- **防呆** ✅：收尾时 `Get-ChildItem -Filter '_*'` 查一遍。

### C-5 自审/检查工具做得太粗
- **现象**：第一版文档路径检查器报 **277** 个"失效引用"，收紧后还报 **116** 个 ——
  把 shell 命令、HTTP 路由、正则、npm 包名都当成文件路径。
- **规则**：写检查工具**先定义判定口径**（什么算失效），再写规则；宁可少报也不要噪音淹没真问题。
- **防呆** ⚠️：先手写 5 个正例 5 个反例验证检查器本身。

## D. 交付质量

### D-1 文档里的路径/数字不自洽
- **现象**：自审查出 3 处 —— `backend/tests/...`（该目录不存在）、`backend/README`（缺 `.md`）、
  同一文档里"287 passed"与"300 passed"并存。
- **又犯一次（同步 `架构图.md` 时）**：v1.0 的图与代码**脱节 7 处**（错误码 12→15、
  OCR 缓存路径写错、前端端口写死 5173、"只有 3 条规则用 LLM"实为 4 条、
  唯一索引写 4/6 个实为 7 个、把 `match_mode` 当成主要分派机制、`contract_parses` 关系画成 1..1 实为 1..n）。
  **没有一处是有人报错才发现的** —— 是主动逐项核对代码才翻出来。
  根因：图写完就再没跟代码对过；`§E 清单第 4 条`当时只写了标题、**没写命令**，等于没有这道检查。
- **规则**：**改完文档立刻复核上下文**；改数字要 grep 全仓同步；路径要能解析到。
  **图与数字必须"代码能指出来"**：每张图/每个结论都要标注依据（文件路径或 SPEC 编号），
  否则下次没人能验证它是否还成立。
- **防呆** ⚠️：交付前跑一遍"文档路径引用 + 关键数字"自检。
  改架构类文档前，先核对这三样最容易脱节的：**路径类配置、数据库唯一索引、规则/枚举分布**。

### D-2 文档里给的命令没在目标 shell 上真跑过
- **现象**：README 里的重新灌种子命令用 `Get-Content -Raw | docker exec …`，
  在 PS 5.1 下会按 ANSI 解码**无 BOM** 的 UTF-8 SQL 文件 → 中文变乱码再灌进库。
- **规则**：写进文档的每条命令都要**真跑一次**（或在文档里注明适用 shell 与版本）。
- **防呆** ⚠️：命令用 `cmd /c type`（保留原始字节）这类与 shell 编码无关的写法。

### D-3 样例覆盖不足，掩盖了真实缺陷
- **现象**：原有 5 份样例只覆盖"路径"，没有 Word 样例、没有合并标题样例，
  于是 R011 词表过窄、解析器"一标题只归一字段"这两个缺陷一直没被测出来 ——
  是新写的 4 份自查合同（`sample_contracts/extra/`）才把它们翻出来。
- **规则**：补样例/用例要覆盖 **格式 × 措辞** 两个维度（PDF/Word/扫描件 × 常见写法变体），
  不能只覆盖"代码分支"。
- **防呆** ⚠️：新增规则或解析逻辑时，同时问"真实合同的另一种写法会怎样？"

### D-4 只判"端口返回 200"就认定"我的服务在跑" —— 结果是别人的项目
- **现象**：**同一个坑踩了两次**。
  1. `scripts/dev_up.ps1` 判断前端"已在运行"的条件只是 `http://127.0.0.1:5173/` 返回 200。
     本机另一个项目（InsightTrace）的 dev server 正占着 5173，于是**我们的前端从来没被启动过**，
     而脚本却报"已在运行"，白白排查了很久。
  2. `tests/test_m7_ui_e2e.py` 把 `WEB_URL` 写死成 `5173`，`_web_ready()` 同样只判 200。
     全量回归于是**去点别人的界面**：`295 passed, 7 errors`，而且报错信息指向本项目的代码，
     极具误导性（真实原因是页面根本没渲染我们的列表）。
- **根因**：把"**端口上有东西**"当成了"**端口上是我的东西**"。端口是共享资源，
  本机同时存在多个项目时，"200" 完全不构成身份证据。
- **规则**：凡是连接**本机端口上的服务**（探活、代理、浏览器自动化、健康检查），
  判定条件必须包含**身份证据**（页面标题/响应体特征字符串），不能只看状态码。
  端口冲突时**自动顺延或明确报错**，绝不静默复用别人的服务。
- **防呆** ✅：`dev_up.ps1` / `dev_status.ps1` / `test_m7_ui_e2e.py` 三处已统一为
  "5173–5180 顺序探测 + 页面含 `ClauseGuard` 才算数"；测试另支持
  `CLAUSEGUARD_WEB_URL` 环境变量指定。**新增任何探活逻辑时先问：这个 200 一定是我的吗？**

### D-5 把"某一份样例的结论"写死进脚本 —— 换一份样例就假失败
- **现象**：`scripts/demo_closed_loop.py` 提供了 `--instance`，但脚本里写死了 **AP-001 的期望值**：
  `parse_mode == "text"`、`contract_type == "采购合同"`、`overall_risk_level == "high"`、
  `1 <= 关注点 <= 5`。换样例跑就"失败"：AP-007（条款齐备的对照组，期望 **low / 0 命中**）
  报 `21/23`、AP-008 报 `22/23`。**数据是对的，判据是错的** ——
  而且这种假失败最容易骗人：看到"未通过"就先去查项目，真正的错处在脚本自己。
- **规则**：**期望值只能有一个来源**。本项目已有 `sample_contracts/expected_results.json`
  （SPEC §15 SD-01 的单一事实来源），脚本就该读它，而不是在代码里再抄一份；
  派生量（如"零命中 ⇒ 0 条关注点"，由 `summarizer.active_hits` 决定）要**跟着派生逻辑写判据**，
  不能跟着某一次观测值写死。
- **防呆** ✅：新增 `load_expected(instance_id)` 统一读取；无期望值的样例只跑通用判据。
  改完必须把**默认样例 AP-001 也重跑一遍**，确认主路径没被改坏。

## E. 每次交付前的固定检查清单

跑完下面 6 条再宣布"完成"：

```powershell
cd ClauseGuard

# 1) 工作区干净、三方同步一致
git status -sb                                  # 无 ahead/behind、无未提交
git rev-parse main; git rev-parse origin/main   # 两者相同
git ls-remote https://github.com/lihaozhen-max/ClauseGuard.git HEAD   # 远端哈希亦相同

# 2) 全量回归（需 8000 + Chrome + 调用端 dev server；调用端端口由页面身份在 5173–5180 上自动定位）
cd backend; uv run pytest -q; cd ..

# 3) 前端类型检查与构建
cd frontend-or-client; npm run typecheck; npm run build; cd ..

# 4) 文档路径引用与关键数字自检（数字不得自相矛盾）

# 5) 敏感物审计：跟踪文件中不得有 .env / .venv / node_modules / dist / storage / _logs / 模型文件
git ls-tree -r --name-only origin/main | Select-String '\.env$|\.venv/|node_modules/|/dist/|storage/|_logs/'

# 6) 临时文件与借用槽位残留（`_*`、`*.bak`、AP-004 附件）
Get-ChildItem -Force -File | Where-Object Name -like '_*'
Get-ChildItem sample_contracts -Filter 'AP-004*'
```

**汇报口径**：结论分三档写清楚 —— ✅ 已验证（附命令输出）、⚠️ 未验证/未覆盖、⛔ 明确不做（附理由）。
不许把 ⚠️ 写成 ✅。
